# 2026-09-29

## 修复 SqlSugarSetup 初始化 Sqlite 报 SQLite Error 14

**现象**：`Dji.Core/SqlSugar/SqlSugarSetup.cs` 第 289 行 `dbProvider.DbMaintenance.CreateDatabase()` 抛
`Microsoft.Data.Sqlite.SqliteException`（内部 rc=14：`SQLite Error 14: 'unable to open database file'`）。

**根因**（已用最小复现工程在 SqlSugarCore 5.1.4.221 + net10.0 下逐条验证）：
- 连接串来自 `Dji.Application/Configuration/Database.json`：`DataSource=./db/dji.admin.db`（主库）/ `./db/dji.log.db`（日志库）。
- SqlSugar 的 `SqliteDbMaintenance.CreateDatabase()` 只用正则从连接串里抠目录，且**只有 Windows 盘符绝对路径**（`[a-zA-Z]:\...\`）才会自动 `CreateDirectory`；
  相对路径（`./db/xxx.db`、`db/xxx.db`）走到 `Ado.Connection.Open()`，不建目录。
- SQLite 自身（sqlite3_open_v2）也不会创建父目录 → SQLITE_CANTOPEN(14)。
- 实仓库里从来没有 `db/` 目录（`Dji.Web.Entry/db/` 曾被提交进 git，后又从工作区删掉，且已被 .gitignore 忽略），故首次以 Sqlite 启动必崩。

**对照实验结论**：`./db/a.db` ❌ / `db/c.db` ❌ / `./b.db`（无子目录）✅ / 绝对路径（含多级子目录）✅（SqlSugar 自动建目录）。

**修复**：`SqlSugarSetup.cs` 新增两个私有方法并在 `InitDatabase`（置顶，早于 EnableInitDb 判断）与 `InitTenantDatabase` 中调用：
- `EnsureSqliteDbDirectory(DbConnectionConfig)`：仅处理 `DbType.Sqlite`，解析 DataSource 后 `Directory.CreateDirectory`；
  跳过 `:memory:` 与 `file:` URI；相对路径按「当前工作目录」创建，与 Microsoft.Data.Sqlite 的解析基准保持一致。
- `ResolveSqliteDataSource(string)`：优先用 `Microsoft.Data.Sqlite.SqliteConnectionStringBuilder`（兼容 Data Source/Filename 别名、引号），
  非标准关键字抛异常时退化为手工 `;` 切分解析。

**验证**：`dotnet build` 0 错误；实际启动 `Dji.Web.Entry`（CWD=Dji.Web.Entry）无任何异常，自动生成
`db/dji.admin.db`（54 张表）与 `db/dji.log.db`（5 张表），种子数据写入正常。

**副作用提醒**：验证运行重新生成了被 git 跟踪的 `Dji.Web.Entry/db/*.db`（内容变为全新库）。
`.gitignore` 已忽略 `Dji.Web.Entry/db/`、`*.db`，建议后续 `git rm --cached Dji.Web.Entry/db/*.db` 解除跟踪。

**环境**：net10.0 / SqlSugarCore 5.1.4.221（依赖 Microsoft.Data.Sqlite 10.0.11）/ Furion 配置目录 `Dji.Application/Configuration`。
